# Подключаем ZvenoAI к n8n без VPN

Учебная инструкция для первого модуля. Основана на https://zveno.ai/integrations/n8n. Для регистрации используется **реферальная ссылка автора** https://zveno.ai/?ref=plMvItdv. Использование ссылки не означает гарантированную скидку. Все ответы по моделям и тарифам проверяйте в кабинете.

## Что получим

В интерфейсе n8n создадим собственный workflow из трёх узлов. Введём сообщение, отправим его через ZvenoAI к выбранной модели и получим ответ. До этого момента не нужны импорт JSON, инструменты, память и Python.

## Шаг 0. Запускаем n8n

n8n — визуальный редактор автоматизаций. Можно использовать собственный self-hosted экземпляр, в том числе Docker на компьютере. В наборе курса есть examples/docker-compose.yml. Для локального запуска задайте приватный N8N_ENCRYPTION_KEY и выполните docker compose -f examples/docker-compose.yml up -d. Перейдите по http://localhost:5678 и завершите создание владельца инстанса. Не открывайте порт 5678 напрямую в интернет.

## Шаг 1. Регистрируем ZvenoAI и получаем ключ

1. Откройте https://zveno.ai/?ref=plMvItdv — реферальная ссылка автора курса.
2. Зарегистрируйтесь или войдите. Перейдите в https://zveno.ai/api-keys.
3. Создайте API-ключ, сохраните его в защищённом месте. Не вставляйте ключ в Stepik, GitHub, JSON workflow или скриншот.
4. Посмотрите https://zveno.ai/models и текущую стоимость нужной модели. Запросы тарифицируются отдельно от n8n.

## Шаг 2. Настраиваем Credential OpenAI

1. Откройте n8n и найдите Credentials → Create Credential → OpenAI. В отдельных версиях credential можно создать прямо из узла Chat Model.
2. В поле API Key вставьте ключ ZvenoAI.
3. Поле Organization ID оставьте пустым.
4. В Base URL укажите точно https://api.zveno.ai/v1.
5. Сохраните credential. Проверка подключения должна обратиться к каталогу моделей. Если проверка успешна, это ещё не значит, что конкретная модель способна выполнять tool calling.

## Шаг 3. Рисуем первую схему самостоятельно

1. Создайте New Workflow.
2. Добавьте When chat message received (Chat Trigger).
3. Добавьте AI Agent и соедините с ним Chat Trigger.
4. Под нижним портом Chat Model у AI Agent нажмите плюс и добавьте **OpenAI Chat Model**.
5. В OpenAI Chat Model выберите только что созданный Credential ZvenoAI.
6. В Model выберите полный идентификатор из каталога, например google/gemini-2.5-flash. Если модель не предлагается списком, в зависимости от версии узла выберите ручной ввод ID.
7. Сохраните workflow.

Важно: не путайте подузел **OpenAI Chat Model** с отдельным app-узлом OpenAI, включая Message a Model. В исходной инструкции ZvenoAI предупреждают о проблеме кастомного Base URL у app-узла.

## Шаг 4. Тестовый запуск

Нажмите Execute Workflow, откройте тестовый чат и отправьте «Привет. Ответь по-русски одним предложением». Убедитесь, что выполнение завершилось и вы получили ответ. Откройте https://zveno.ai/dashboard и проверьте наличие использования и расход. Если нет ответа, сохраните текст ошибки без секретов.

**Результат:** вы самостоятельно подключили модель через ZvenoAI к n8n. Только после этого переходите к готовым проектам и инструментам.

## Дополнительный способ. HTTP Request без AI Agent

Когда нужен один запрос к модели, а не агент, используйте узел HTTP Request.

- Method: POST
- URL: https://api.zveno.ai/v1/chat/completions
- Authentication: Generic Credential Type → Header Auth
- Header: Authorization
- Value: Bearer <ваш API ключ>, но секрет хранится в Credential, не в экспорте JSON.
- Body Content Type: JSON

Пример тела запроса:

```json
{
  "model": "google/gemini-2.5-flash",
  "messages": [
    {"role":"user","content":"Объясни простыми словами, что такое n8n."}
  ]
}
```

Результат текстового запроса обычно находится в choices[0].message.content. Конкретный ответ и название модели зависят от фактического выполнения.

## Embeddings

Узел Embeddings OpenAI использует тот же Credential. Для генерации векторов выбирайте именно embedding-модель из https://zveno.ai/models?modality=embeddings. Обычная чат-модель не становится embedding-моделью от выбора в другом узле. RAG рассматривается после освоения базового чата.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Credential принят, но отдельный OpenAI app-узел падает | Используйте подузел OpenAI Chat Model или HTTP Request |
| 401 | API Key, сохранённый Credential и адрес Base URL |
| Model not found | Полный идентификатор vendor/model-name и каталог |
| 429 | Лимиты, баланс, допустимую частоту; не включайте бесконечные повторы |
| Долгий ответ | Настройки timeout и выбранную reasoning-модель |
| Ответ есть, но инструмент не вызван | Поддержку tool calling и execution инструмента; это отдельная проверка |

## Варианты моделей

В официальной статье перечислены anthropic/claude-sonnet-4.6, openai/gpt-5.2, google/gemini-3.1-pro-preview и google/gemini-2.5-flash. Это примеры из источника, не обещание, что все четыре доступны в аккаунте в любое время. Для урока используйте модель с доступным текстовым API. Для последующих уроков с tools нужна дополнительно проверенная поддержка function/tool calling.
